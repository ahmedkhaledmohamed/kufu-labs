Keep streamed neural data intact during inspection

A converter checks a stream of samples before writing an NWB file. The inspection can consume part of the stream, leaving the later writer with missing values that become zeros in the saved file.

Local data-preservation result; upstream adoption unvalidated

Who encounters it and why it matters

Researchers and engineers converting streamed neurophysiology data into NWB files.

Preserve the original samples when software inspects them before saving. Scientific conclusions and real-recording usefulness remain unvalidated.

Science and terms

Neurophysiology recordings can be large, so software may handle them a chunk at a time. The saved sample sequence must match the input. Preserving samples is a data-integrity requirement; it does not establish that the experiment or its interpretation is correct.

NWB
Neurodata Without Borders: a format and ecosystem for organising neurophysiology data.
Stream / iterator
A source that yields successive chunks; reading a single-pass source advances it.
Shape inspection
Asking how many samples and channels an object contains, without intentionally analysing the signal.

Where the problem appears

  1. Receive a stream

    Constructed positive samples arrive in chunks.

  2. Inspect before writing

    The real Inspector checks the NWB object.

  3. Save and reopen

    The real HDF5 or Zarr writer and reader execute.

  4. Compare every value

    The replay checks the complete sequence and dtype against input.

Evidence and existing tools

Pinned NWB Inspector e6d968a with PyNWB 4.2.0 and HDMF 6.2.0; related HDMF PR #1606 remains open when checked.

  • NWB Inspector data-loss report #771
  • Related shape-helper proposal #760
  • Dependency fix PR #1606

The solution being tested

The patch reuses HDMF’s existing shape helper instead of the Inspector’s local helper. In the tested wrapped-stream workflow, inspection no longer consumes data that the writer still needs. An upstream proposal already suggested helper reuse; Kufu’s contribution is the bounded patch, reproduction and regression evidence.

Existing inspect_nwbfile_object workflow; upstream utility patch, not a new application.

Before and after the inspection patch

The input contains no zeros. The baseline returns inspection errors, but writing still succeeds; it must not be described as a silently passing inspection. Uninspected controls preserve the data.

Validation and limits

12 inspected HDF5/Zarr cases lose values at baseline and preserve every value with the patch. All 12 uninspected controls per revision preserve values. Broader unit run: 341 passed, 5 skipped.

What remains unverified

No real recordings, full version matrix, upstream acceptance or researcher benefit. The required scientific CI replay and protected production delivery passed in main run 40613968067.

What would count as resolving it

The supported inspection/save workflow preserves all input values without weakening checks, and the preferred design is independently reviewed.

Next step

Review the existing-helper integration and contribution package; upstream discussion remains deferred.
