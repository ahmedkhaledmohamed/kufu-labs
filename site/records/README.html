Kufu Labs

Kufu (工夫, *kufū*) is Japanese for devising better ways to do something: practical ingenuity. Dictionary source.

An open-source lab for building and testing small tools around reported research-workflow problems. Each exploration connects an original problem report to an intended user, an implementation and evidence of what has actually improved.

Research scope and candidate problems

Kufu investigates scientific software gaps across domains. The current research includes microscopy, neuroscience, biomedical evidence, bioinformatics, accessibility and research methods. Pose tracking is the first implemented exploration; it does not define the lab's scope or determine the next project.

The problem board contains 25 candidate tasks, including hypotheses and deferred ideas. The source directory links 15 boards and directories where needs, priorities and challenges are reported. These are curated research snapshots, not an exhaustive list of unsolved problems or confirmation that each proposed tool is needed.

Implemented work and remaining proof

  • **Pairwise overlap inspector:** a browser inspector of seven constructed examples for people proofreading overlapping pose predictions. It shows unchanged filter output and its explanation. It could reduce trial-and-error when choosing settings, but does not accept users' own poses or integrate into SLEAP. Prevalence, time saved and better decisions are unmeasured.
  • **movement edit-aware filtering:** a local patch preserves an explicit correction while dropping an unscored prediction in the tested workflow. Reproducible Qt/model-event checks cover that subproblem. The broader upstream request, rendered user interaction and practical user benefit remain unvalidated.

These pilots provide technical evidence for specific tasks. They do not establish that pose tracking deserves priority over the other areas. No end-to-end user problem is claimed resolved.

Explore and run

Live site: kufu-labs.vercel.app (Vercel sign-in).

Open Home, Explorations, Problems, Sources or Validation. Each tab is an independent page; the interactive pose demo can open in a separate browser tab. Exploration entries describe the runtime, constructed inputs, launch command, expected result and verification limits.

Run npm ci --ignore-scripts --no-audit --no-fund, then npm run build and npm test. Serve the reviewed package with python3 -m http.server 8879 --bind 127.0.0.1 --directory dist. See delivery for pinned scientific checks, the protected Vercel pipeline and retained evidence; WORKSPACE.md records actual publication/deployment state.

Structure and boundaries

research/ preserves sourced investigations and decisions. projects/<name>/ keeps each contribution, executable check, source pin and limits. site/catalog.json is the maintained hub catalogue; site/build.py generates the root website and safe, readable copies of the Markdown research records. Keep upstream implementation checkouts separate.

The deletion diagnostic records an unfixed repeated-export provenance defect. The coordinate-filtering result and this remaining defect are kept separate. Source revisions, patches, commands and outcomes live with each project.

No recordings, model weights, environments, patient information or credentials belong in the repository. Dataset, model and software licences are independent. A passing check does not establish scientific correctness, adoption, clinical utility or researcher benefit.

Retain the applicable project and upstream notices when redistributing. These software licences do not grant rights to recordings, model weights, external datasets or linked publications.

The CI pipeline must verify the tested artifact and current main before promotion. Publication still follows full-diff/contribution-record/exact-commit approval and explicit PR merge authorisation.
