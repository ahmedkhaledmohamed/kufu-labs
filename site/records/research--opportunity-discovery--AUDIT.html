Scientific software candidate audit

Assessed 26 October 2026. This primary-source and code-inspection audit preceded the subsequently approved technical pilot. At this audit stage no candidate software was installed or executed; no research images, model weights, or literature corpus were downloaded. Public source files, manifests, and issue metadata were inspected. Resource caps below are proposed limits, not measured requirements.

Decision

Recommend the bounded movement filtering pilot. Its public request and current source support a specific missing capability. Defer microscopy and evidence retrieval: there is evidence that their scientific tasks matter, but this audit did not establish a novel, maintainable software contribution within them.

This ranking concerns the strength and feasibility of a first contribution. It does not rank the importance of the underlying sciences or establish personal satisfaction from the work.

1. Label-free microscopy

Task and beneficiary. A cell-imaging researcher wants to estimate a fluorescence channel from transmitted-light images. The Light My Cells programme and dataset paper establish the research task. Whether a predicted channel is adequate for a particular biological measurement requires a microscopy reviewer; plausible appearance is insufficient.

Existing implementation. BiaPy v3.7.1, released 10 September 2026, resolves to aa7c08e32364eb0186c9006109c47b4b8570172d. Its Light My Cells tutorial already describes reusable models for four channels. napari-bioimageio already offers model discovery and inference, although it describes itself as alpha. A generic model selector or prediction viewer would overlap with these tools. Other challenge repositories inspected were MMV-Lab, MWod, and MedICL-VU; incomplete checkpoint documentation in a README does not establish a missing capability across the ecosystem.

Model and licence. BiaPy code is MIT licensed. The BioImage Model Zoo artifact metadata identifies the nucleus model as version 0.1.0, CC-BY-4.0, with a PyTorch state dictionary. The checkpoint SHA-256 is e823220442b47be5ebd88d64d69e2ff0f1856154466455d7e3af5b8702e85770. The model specifies one 1024 × 1024 float32 channel and PyTorch 2.4.0+cu118; the pinned BiaPy release requires Python 3.11+ and Torch 2.9+. The published environment lists Python and timm without fully pinning every dependency. These are compatibility questions to reproduce, not proof of incompatibility. A rolling tutorial must not be treated as a tested release lockfile.

Data access and size. The anonymous BioStudies study API, archive information endpoint, and Study 1 file manifest were successfully read. The study metadata specifies CC BY 4.0. The manifest lists 129 Study 1 files totalling 719,341,776 bytes. One brightfield/nucleus pair is:

  • Images/Study_1/image_0_BF_z0.ome.tiff: 5,769,226 bytes.
  • Images/Study_1/image_0_Nucleus.ome.tiff: 4,701,218 bytes.
  • Combined: 10,470,444 bytes; the images themselves were not fetched.

The archive reports 56,984 files; its abstract reports 56,981 images. File and image counts are different quantities and should be reconciled before an experiment. Challenge registration is not necessary to read these archive manifests; actual image transfer has not been tested. Code, model, and dataset licences are separate.

Integration and evaluation boundary. Start with BiaPy image-to-image inference on a permitted pair, then evaluate by held-out study/acquisition group rather than splitting neighbouring images randomly. The grouping's adequacy and biological independence remain unverified. Only after a real measurement need is identified should napari display separate observed and predicted layers with portable image outputs and model provenance. Existing BiaPy/BioImage.IO functionality is the baseline; no new plugin API was exercised.

Resources and maintenance. Weight size, peak inference memory, CPU viability, and minimum GPU are unmeasured. Training hardware is not an inference minimum. A future feasibility session should cap image downloads at 1 GB, avoid training, use existing local hardware, and stop if it requires paid compute or unresolved model execution. Model formats, preprocessing, dependency differences, and acquisition shifts create substantial maintenance and scientific-review work. BiaPy and BioImage.IO communities are plausible review routes; nobody has agreed to review this project.

Disposition. Defer. A paired-image error/measurement audit could be worthwhile, but no specific researcher workflow or inadequacy of existing evaluation has been established. A deployment plugin alone is not justified.

2. Behavioural neuroscience: explicit manual-edit provenance

Task and beneficiary. Researchers proofreading animal pose tracks need filtering to distinguish manually corrected coordinates from predictions with missing scores. movement issue #1027, open and unassigned when checked, describes separating edit status from model confidence and using that status in filtering. This is direct community evidence for a task, not proof of its prevalence or a commitment to accept our implementation.

Pinned baseline. The BSD-3-Clause movement repository was inspected at main revision 39ee15e29706150d7d4f60ba617aa99d2027eed7 dated 26 October 2026. The latest release API reported v0.17.0, published 8 June 2026; the proposed contribution targets the later inspected main, not an assumption that release behaviour is identical. Its project metadata requires Python 3.12+, xarray, NumPy, and existing IO dependencies; napari is an optional GUI dependency. Cached rolling documentation was older than this source, so the pinned source controls this assessment.

What already exists. The napari conversion source already carries a boolean edited variable. The edit callback marks moved points and sets their confidence to NaN. Conversion also marks removed points. Native netCDF and GUI reload preserve edit state where the corresponding keypoint/individual remains. A new edit mask, timeline, or generic proofreading GUI would duplicate work.

Remaining gap. The pinned confidence filter accepts confidence, threshold, a NaN-confidence policy, and reporting; it accepts no edit provenance. With missing confidence on both a corrected point and an unscored prediction, its existing policy keeps both or drops both. PR #1037 explicitly describes the NaN policy as a short-term solution and points to #1027 for the longer-term change. An optional explicit provenance input could address this remaining distinction using the existing field. It must not infer human review from NaN alone.

Competing work checked. Searches for issue #1027 and PRs mentioning edited/manual-edit/confidence found the existing mask, saving, reset, and timeline work, but no matching provenance-aware filter PR. Search is bounded and cannot exclude unpublished or differently described work; refresh before implementation. Several other plausible contributions were rejected:

Data, access, and resources. The first pilot needs a tiny synthetic xarray pose dataset rather than animal recordings: dimensions time/space/keypoint/individual, a confidence array, and the existing boolean edit field. There are no external access conditions or subject-level split requirements for these constructed cases. A two-individual fixture under 1 MB can exercise coordinate alignment, missing positions, and native save/reload. movement's sample registry uses external GIN metadata and per-file hashes; research sample licences were not established, so those files are not authorised inputs to this proposal. This avoids inventing licence clearance or downloading large videos. CPU-only execution is plausible for these operations but has not been measured; proposed limits are in the pilot.

Integration and support. The existing workflow is napari proofreading → movement Dataset/native netCDF → Python or notebook filtering → ordinary analysis. Add an explicit argument to the existing library function, with existing behaviour unchanged when omitted; no additional application, service, or plugin is needed. Restrict the first task to movement's own explicit edit field. SLEAP provenance extraction, NWB provenance export, original-prediction retention, and biological event classification are separate work.

Review and maintenance. A movement maintainer can judge API compatibility and alignment semantics; a behavioural researcher must assess usefulness in real analysis. The contribution guide encourages discussion before coding and requires the project's testing/formatting practices. The Neuroinformatics Unit community is a plausible review route, not an agreed collaborator. An additive function option and targeted tests have a smaller maintenance surface than a separate plugin, but field/schema changes and upstream design preferences can invalidate the proposal.

Disposition. Retain for a bounded technical pilot, subject to approval and a refreshed duplicate-work check. It establishes provenance-sensitive behaviour, not that manual corrections are ground truth or that downstream neuroscience improves.

3. Biomedical evidence retrieval

Task and beneficiary. Biomedical researchers need relevant evidence and grounded answers. NIH/NLM's SPARK requirements distinguish known-item retrieval from exploratory evidence synthesis and specify relevance/grounding evaluation. They support a real research problem; they do not establish a missing general-purpose assistant.

Existing baseline. Apache-2.0 PaperQA v2026.08.12, released 12 August 2026, resolves to 57e89f7223b0960d5ee5ea048c69e3c47e088572. Its release README describes retrieval, cited answers, and local Ollama configurations. Current-main metadata inspected at c692d0dfeac4a0296599f7fe21a253a58b7ac12a supports Python 3.11–3.14. This is an established library/CLI boundary for notebooks or scripts. A new chatbot would duplicate its broad purpose; no selected baseline configuration has yet failed an independently judged question.

Competition access and limitations. SPARK describes a frozen PubMed baseline through July 2026, a permitted PMC subset, registration-gated evaluation materials, public/open-weight model requirements, and containerised execution. External proprietary LLM APIs are excluded for challenge execution. The page's submission-stage wording needs reconciliation before participation. No registration was performed. BioASQ lists training questions but restricts downloads to registered users; its listing alone does not settle reuse rights.

Small independent data option. SciFact provides scientific claims, evidence abstracts, labels, and rationales. Its original licence separates CC BY 4.0 claims/annotations, ODC-By 1.0 abstracts, and Apache-2.0 code. The publisher's Hugging Face mirror card instead labels the dataset CC-BY-NC-2.0 and lists a 3.12 MB download with approximately 11.11 MB generated corpus storage. These conflicting labels must be resolved against the exact upstream artifact before reuse; no dataset was downloaded. Its loader also requires arbitrary Python execution, so an explicit JSONL route would be preferable to trusting a remote loader. SciFact is claim verification, not a substitute for SPARK's full evaluation task. Questions and abstracts must remain grouped to prevent evidence leakage between tuning and evaluation.

Corpus rights. PMC OAI-PMH and the Open Access service distinguish metadata from reusable full text and expose article-level licensing. Availability in PubMed or PMC does not itself grant a uniform redistribution licence. An independent pilot should keep source identifiers and permitted passages, rather than republishing an indiscriminate corpus.

Resources, expertise, and maintenance. A lexical retrieval baseline on a small abstract corpus could avoid model weights, but would not test PaperQA's complete local-model workflow. Ollama model weights, embedding weights, memory, indexing latency, and answer cost are unmeasured. A future pilot must choose and license exact model versions, set local storage/runtime caps, and avoid assuming that a no-fee API is a sustainable service. Biomedical expert review is needed for citation support and unanswered cases; annotation labels alone do not establish end-user utility. Citation parsing, model/provider changes, corpus rights, and benchmark drift create continuing maintenance. Neither PaperQA maintainers nor a biomedical reviewer have been contacted.

Disposition. Defer. A failure-specific citation or abstention improvement might be valuable, but no demonstrated gap or reviewed baseline justifies choosing it now. Free software distribution would not eliminate inference and review costs.

Completion and limits of this audit

All three candidates now have a primary-source task, existing baseline, access/licence assessment, integration boundary, resource uncertainties, maintenance assessment, and retain/defer decision. Only movement has a narrow missing capability supported by both a public request and pinned source. At audit completion its proposal was ready for review. Runtime reproduction has since passed in the local pilot; external validation remains a future gate. None of this research establishes clinical effectiveness, user adoption, or agreement to accept a contribution.
