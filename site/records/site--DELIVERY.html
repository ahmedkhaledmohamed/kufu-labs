Runtime and navigation

Home, Explorations, Problems, Sources and Validation are independent HTML documents. Ordinary navigation changes page URLs; the interactive pose demo action opens a separate tab. Each software entry lists its runtime/version boundary, constructed inputs, launch command, expected result, verification evidence and limitations.

The hub and pose inspector are browser software. The movement example runs the actual pinned Python/Qt host in an isolated local or CI environment. Build and inspect

Use Node 22 and Python 3.13. A local .npmrc selects the public npm registry.

npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm test
DEMO_OUTPUT=.runs/overlap npm run test:overlap
python3 -m http.server 8879 --bind 127.0.0.1 --directory dist

Playwright needs an installed browser. Locally CHROME_PATH can point to an existing Chrome executable; CI installs its matching Chromium with npx --no-install playwright install --with-deps chromium. No research recordings, model weights or training are used.

site/build.py validates the catalogue and generates the pages/research views. site/package.py copies an allowlist of static pages, records, result files and tracked research/project download types into ignored dist/. It excludes environments, credentials, .git, CI scripts and untracked project files. build-info.json records the source commit, dirty-source flag and SHA-256 of each packaged asset; a dirty local build is not falsely presented as a clean release.

CI stages and evidence

The immutable-action-pinned lab-delivery.yml workflow runs on PRs, main pushes and manual dispatch:

  • Scientific contracts: source-only checkouts of movement at the recorded revision, one with the unchanged approved patch and one clean; actual sleap-nn modules and licence checked against pinned hashes; CPU-only Torch; real offscreen Qt/widget replay; independent deletion reproduction. Pip environment and failure logs are retained. A reproduced deletion bug is a negative result, not a fixed defect.
  • Web: consume that run's CPU-generated pose demo, install locked tooling, lint, build once and verify five-page navigation, filters, source/deep links, demo tab, validation scope, mobile layout and local document targets. Test the full pose boundary UI. Retain the exact tested site plus screenshots and offline browser traces.
  • Delivery: download the tested artifact, verify each hash and its commit, verify the exact Vercel project/team and all-deployment protection, deploy without rebuilding and run authenticated browser checks against the deployed site. Verify unauthenticated requests cannot read the hub, catalogue or demo. A main release uses --prod --skip-domain, is checked for stale-main races, then explicitly promoted through the project API. Generated aliases may already be assigned before this promotion; the flag skips custom domains, not all generated routing. Same-repository PRs receive protected unpromoted previews; fork PRs receive no deployment secrets.

For a brand-new Vercel project, the first deployment can be production-targeted even when requested as a preview. The script uses --prod --skip-domain for that bootstrap and never explicitly promotes it from a PR. Actual main deployment metadata showed autoAssignCustomDomains: false while the generated .vercel.app alias was assigned. Do not interpret the flag or CLI wording as proof that all aliases stayed unchanged. All deployments remain authenticated. Only current main, after both verification jobs and deployed browser checks succeed, can request explicit promotion.

Reports/screenshots/traces are GitHub Actions artifacts retained for 14 days. Their visibility follows the repository visibility; publishing the repository also exposes its Actions history. Authenticated remote traces are deliberately disabled: traces can capture request headers, so only offline traces are retained. Remote reports/screenshots contain no verification credential. Longer-term example result files in the repository are dated evidence, not an assertion that the latest cloud workflow has passed.

Vercel configuration

Verified target: personal scope ahmed-khaled-mohameds-projects, project scientific-software-lab. site/deployment-config.json contains non-secret identity constraints; the deployment script checks them before mutations. Vercel Authentication is configured for All Deployments, covering production and preview. No paid protection add-on, new account or purchased domain is used. Implicit Git linking is disabled so a separate integration cannot bypass the CI promotion gate.

A verified CLI limitation (upstream #17506) makes a fresh CLI profile request user/team metadata even when its project-scoped token can access the project. The delivery script creates a temporary private CLI profile containing only the already verified team-ID mapping, passes it to every Vercel command and removes it afterward. It stores no token in that profile, grants no broader access, and retains the server-side token restrictions plus explicit project/owner/protection checks. A short-lived project token confirmed direct project access and CLI access with that mapping; the original PR run's scientific and browser checks passed before its deployment preflight exposed this limitation. The cached scope mapping passed cloud preview deployment. The high-level promote command still performs additional user/team lookups, so the fix uses the documented project promotion endpoint via vercel api, retaining the same project-scoped token. Before POST it verifies deployment project, owner, source commit, production target and ready state. An empty successful mutation response is accepted; required reads still require JSON. It waits up to three minutes for the current production target to match the exact deployment ID, ready state and source commit, then verifies the served alias and artifact. Optional lastAliasRequest metadata can reject a failed/skipped job but is not required: the real API omitted it after successful promotion. Failed, skipped, unrelated or timed-out promotion cannot produce a success record. The project-scoped API performed the real promotion in main CI; the final response-handling and completion-observation fix still needs a green cloud run.

GitHub Secrets contains a project-scoped VERCEL_TOKEN (90-day lifetime, rotate before expiry) and a project-specific VERCEL_AUTOMATION_BYPASS_SECRET for browser verification. Values are never placed in source, process arguments, logs or browser traces. Vercel CLI telemetry is disabled. Use secret rotation to replace credentials; do not weaken protection to make a check pass.
