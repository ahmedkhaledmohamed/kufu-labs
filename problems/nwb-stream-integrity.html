Keep streamed neural data intact during inspection

A converter checks a stream of samples before writing an NWB file. The inspection can consume part of the stream, leaving the later writer with missing values that become zeros in the saved file.

Local data-preservation result; upstream adoption unvalidated

Who encounters it and why it matters

Researchers and engineers converting streamed neurophysiology data into NWB files.

Preserve the original samples when software inspects them before saving. Scientific conclusions and real-recording usefulness remain unvalidated.

Science and terms

Neurophysiology recordings can be large, so software may handle them a chunk at a time. The saved sample sequence must match the input. Preserving samples is a data-integrity requirement; it does not establish that the experiment or its interpretation is correct.

NWB
Neurodata Without Borders: a format and ecosystem for organising neurophysiology data.
Stream / iterator
A source that yields successive chunks; reading a single-pass source advances it.
Shape inspection
Asking how many samples and channels an object contains, without intentionally analysing the signal.

Where the problem appears

  1. Receive a stream

    Constructed positive samples arrive in chunks.

  2. Inspect before writing

    The real Inspector checks the NWB object.

  3. Save and reopen

    The real HDF5 or Zarr writer and reader execute.

  4. Compare every value

    The replay checks the complete sequence and dtype against input.

Evidence and existing tools

Public Inspector 0.7.2 and development e6d968a with PyNWB 4.2.0 and HDMF 6.2.0. The same constructed loss is reproduced on both; related HDMF PR #1606 remains open when checked.

  • NWB Inspector data-loss report #771
  • Related shape-helper proposal #760
  • Dependency fix PR #1606

The solution being tested

The patch reuses HDMF’s existing shape helper instead of the Inspector’s local helper. In the tested wrapped-stream workflow, inspection no longer consumes data that the writer still needs. An upstream proposal already suggested helper reuse; Kufu’s contribution is the bounded patch, reproduction and regression evidence.

Existing inspect_nwbfile_object workflow; upstream utility patch, not a new application.

Electrode recording conversion example

A recording converter needs to preserve both the samples and their meaning: which electrode each column belongs to, how integer acquisition counts become volts, and when each sample occurred. This example follows PyNWB’s existing ElectricalSeries workflow using 16 constructed channels. The values and electrode identities are software fixtures, not neural recordings.

Understand the inputs

  • Electrodes and channels: each data column references an electrode-table row. The example deliberately uses reversed table order, so the check verifies the actual links.
  • Acquisition counts and volts: stored integers are multiplied by a voltage conversion and a per-channel factor. The chosen fixture scale is 0.1 microvolt per count; it is not a real device calibration.
  • Sampling rate: 20,000 samples per second gives a 50-microsecond interval. The file stores that rate and a 0.25-second start time.
  • Buffers: the source generates 4,096 time rows at a time. Inspection should ask about its shape while leaving those rows available for writing.

Follow the conversion

The script creates electrode metadata and a buffered integer source, runs the installed Inspector, writes a real HDF5 NWB file, then reopens it. Every value is compared in blocks, and electrode links, voltage factors and timing are checked separately.

Both files still have all 16,384 row positions. However, baseline inspection consumes three buffers before the writer starts, and 12288 rows contain different values. For the first channel at row zero, the generated count is 12514, the baseline saves 0, and the repair saves 12514. Legitimate zeros also occur in the input, so a zero alone is not treated as evidence of corruption.

Both files pass schema validation, which checks the file’s structure. The separate value comparison establishes whether this conversion preserved the generated input. Neither check establishes that a biological experiment is valid.

Memory measurements with larger generated inputs

Generation and readback use bounded blocks. Total process memory also includes Python, NumPy, PyNWB and HDF5. Memory rose with input size; these measurements do not establish constant-memory behavior or a guarantee for larger recordings.

Run the example

Install the experimental repaired wheel in a separate environment, then run this from the lab checkout. The same script can run in an existing notebook whose kernel uses that environment. The output directory must be new.

.venv-nwb-experiment/bin/python projects/nwb-stream-integrity/ecephys.py --expect patched --retain --output .runs/ecephys-example

Validation and limits

12 inspected HDF5/Zarr cases lose values at baseline and preserve every value with the patch. All 12 uninspected controls per revision preserve values. Broader unit run: 341 passed, 5 skipped.

What remains unverified

No real recordings, full version matrix, upstream acceptance or researcher benefit. The required scientific CI replay and protected production delivery passed in main run 40613968067.

What would count as resolving it

The supported inspection/save workflow preserves all input values without weakening checks, and the preferred design is independently reviewed.
