# Lab hub design

The main task is navigating from a reported problem to its evidence, existing tools, local experiment and remaining validation gap. Start with the working portfolio, then an inspectable problem board; avoid a promotional hero or numbers implying scientific success.

Palette: paper #f4f7fb, ink #203b50, ocean #176477, blue #3156a0, muted #64788a, rule #d8e2ec. Use Trebuchet MS for navigation/body and Georgia for the lab title only. No hosted fonts. Left-align content, cap prose at 75 characters, and use a wide evidence table with expandable records rather than columns that imply a Kanban pipeline.

Desktop: compact masthead and anchor navigation; an exploration list beside the validation verdict; full-width problem search/filter/list; source-board directory; validation ledger and next steps. Mobile: stack the portfolio and verdict, turn each problem row into a readable disclosure, preserve all evidence fields, and keep visible focus and explicit labels. No essential motion or colour-only states.

Pre-build critique: a card per scientific domain would hide the actual work and exaggerate maturity. Replace it with named explorations and their real decision state. A generic Kanban would suggest progress towards solving every lead; use selectable stages plus independent evidence labels. The memorable surface is the problem-to-evidence record, with sources always one expansion away.
