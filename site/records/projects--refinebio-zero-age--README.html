Preserve zero-valued age metadata

Status: source-discovered component defect and local patch. No affected public sample, user complaint, production impact or upstream acceptance has been established. Cross-domain investigation.

Problem and possible consequence

The pinned refine.bio harmoniser converts age values to floats and then tests their truthiness before retaining them. Its model metadata method also replaces a zero age with an empty value. A valid numeric zero can therefore be lost at either boundary. Researchers reusing harmonised sample metadata could receive a missing annotation where a submitted source value was zero. The frequency and downstream effect have not been measured.

This is a finding from inspected source and constructed inputs, not a newly reported user need. The related metadata completeness study motivates investigating data reuse but does not establish this specific defect's prevalence.

Actual before and after

At refine.bio 7b809b7, the replay imports the real Harmonizer class with cloud access disabled and network connections blocked. It exercises its full sample-harmonisation method on constructed metadata. The harmoniser replay has no database. A second offline replay exercises the actual Sample.to_metadata_dict method on unsaved model instances with an empty in-memory SQLite annotation table, inert cloud clients and production readiness hooks disabled. This is not a running ingestion service.

Implementation and reproduction

The patch changes the two value-retention conditions in the existing harmoniser and the model metadata age fallback, with targeted tests for both. It accepts a value when it is neither None nor an empty string, preserving numeric zero without converting unknown values to zero. The upstream BSD licence is retained.

Use Python 3.10 and install the minimal pinned requirements into an isolated environment. Create separate baseline and feature worktrees from commit 7b809b7cae8d8a16f635febda80ac0c7336de9d7; apply the patch only to the feature worktree. Then run, from the lab root:

python projects/refinebio-zero-age/verify.py --checkout /path/to/pinned-clean-refinebio --expect baseline --output /tmp/zero-age-baseline.json
python projects/refinebio-zero-age/verify.py --checkout /path/to/pinned-patched-refinebio --expect patched --output /tmp/zero-age-patched.json

To exercise model metadata as well, install the model-fixture requirements in a separate environment and use verify_export.py with the same --checkout, --expect and --output arguments. It imports the actual models and creates only an empty annotation table. It does not save a Sample or run production signals.

The runners reject a different upstream revision. It configures Django without cloud logging, prevents socket connections, compares input metadata before/after, and runs the patch's regression tests for the patched expectation. The raw input annotations are entirely constructed.

Validation limits and next decision

The tested component environment uses Python 3.10.16 and the repository's Django 3.2.18, daiquiri 3.2.1, requests 2.28.2 and retrying 1.3.4 versions. This is not the complete locked service environment. PostgreSQL persistence, production signals, surveyors, output-file generation and the full Django test suite have not run. A component fix is not proof that any researcher has benefited.

Current source already retrieves BioSample metadata. The earlier generic proposal to add BioSample enrichment is therefore deferred rather than duplicated. The project's open production-data-flow issue #3595 is a separate operational concern; an independent app would not resolve it.

The next step is review against the complete upstream test environment and a refresh for competing work. Do not expand this into an enrichment platform. No upstream message, fork push or PR is included. The replay is local and not yet a maintained lab CI gate. Lab publication requires exact-diff approval; upstream outreach remains deferred.
