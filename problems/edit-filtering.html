Keep manual pose corrections during filtering

A person corrects a tracked body-part position, saves the dataset, then filters low-confidence predictions. The corrected point can be removed because its confidence is missing—the same condition used for other unscored predictions.

Technical subproblem addressed locally

Who encounters it and why it matters

Researchers cleaning pose tracks after manually correcting body-part positions in napari.

Keep deliberate corrections while removing other predictions with missing confidence; fewer lost corrections is a hypothesis until assessed in real use.

Science and terms

Pose estimates are coordinates, while confidence scores describe the model output. A manual-edit flag describes where a correction came from. It does not prove the corrected coordinates are scientifically accurate.

Keypoint
A named body-part position at a particular time.
NaN
A missing numeric value. Here, a missing confidence score does not tell us whether a person corrected the point.
Edit provenance
A record that a value was deliberately edited, separate from its numeric position and confidence.

Where the problem appears

  1. Load predictions

    Open a constructed movement dataset in the real host.

  2. Correct a position

    The connected napari event records an explicit edit.

  3. Save and reload

    The host writes and reloads the edited dataset.

  4. Filter using provenance

    The patch distinguishes the correction from other unscored points.

Evidence and existing tools

movement already stores edited flags; PR #1037 provides a coarse NaN policy.

  • Original request #1027
  • Earlier partial workaround #1037

The solution being tested

The patch lets the existing confidence filter accept explicit edited flags. With missing-score retention disabled, it can keep a deliberately corrected point while dropping an unedited prediction with a missing score. Omitting the new input preserves the existing policy.

Existing movement function in scripts/notebooks after napari native save/reload.

Before and after the filtering patch

This comparison disables retention of missing confidence scores in both cases. The existing default can instead keep all missing-score points; it cannot make the explicit-edit distinction.
